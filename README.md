## Гайд по вкладкам и графикам

### 🟦 Обзор

Главная вкладка — общая картина за 5 секунд.

#### 5 KPI-карточек вверху

| KPI | Что показывает | Как считается |
|---|---|---|
| **Текущий остаток** | Сколько денег сейчас на счету | Последний `balance_eod` из выписки |
| **Средний приток / день** | Сколько в среднем приходит | Σ(полож. signed_amount) / дней в истории |
| **Средний отток / день** | Сколько в среднем уходит | Σ(отриц. signed_amount) / дней, дельта = чистый burn rate |
| **Минимум в прогнозе** | Самый низкий прогноз остатка | min(forecast), дельта — дата и через сколько дней |
| **Runway** | Дни до нуля при текущем чистом потоке | current_balance / burn_rate. Если приток > оттока: ∞ |

#### Риск-баннер

Под KPI — большой цветной баннер. Логика:

- 🟢 **СТАБИЛЬНО**: риск 0%, минимум прогноза > 20% от текущего остатка
- 🟡 **ВНИМАНИЕ**: риск 1–20%, или минимум < 20% от текущего
- 🔴 **ВЫСОКИЙ РИСК**: риск > 20%, или прогноз уходит в минус
  - Показывает: дату разрыва, через сколько дней, сумму дефицита, % вероятности

#### Главный график прогноза

- **Синяя заливка** — доверительный интервал 95% (расширяется со временем)
- **Синяя линия** — базовый прогноз (выбранная лучшая модель)
- **Серая линия слева** — фактический остаток из выписки
- **Зелёная точка** — текущий остаток (отсчёт прогноза)
- **Красная пунктирная горизонталь** — нулевой остаток (линия разрыва)
- **Светло-красный фон** — область риска (если прогноз уходит в минус)

#### Дневной чистый поток (бар-чарт)

- **Зелёные/красные бары слева** — фактические потоки по дням
- **Полупрозрачные бары справа** — прогнозируемые потоки
- Позволяет увидеть, какие дни «в плюсе», какие «в минусе»

#### Помесячные притоки и оттоки

- **Зелёные бары** — суммарные поступления за месяц
- **Красные бары** — суммарные списания за месяц
- Помогает увидеть сезонность и динамику бизнеса

## Модели прогноза (математика)

Прогноз считается **тремя моделями одновременно**. После бэктеста
автоматически выбирается лучшая по MAE.

### Модель 1: Weekday Mean

**Идея.** Малый бизнес имеет ярко выраженный недельный цикл:
B2B-оплаты приходят вт-чт, эквайринг растёт к выходным, зарплата и
аренда падают на конкретные числа. Поэтому для каждого дня недели
считаем средний чистый поток за последние 12 недель (84 дня).

**Математика:**

```python
# Для каждого дня недели d ∈ {0..6}:
net_d = mean(signed_amount | operation_date.dow == d
                              & operation_date >= today - 84 days)
# Клиппинг выбросов на 5/95 перцентилях:
lo, hi = quantile(signed_amount, [0.05, 0.95])
net_d = clip(net_d, lo, hi)
# Прогноз потока на будущий день d_future:
flow_t = net_d[d_future.dow]
balance_t = balance_{t-1} + flow_t
```

| + | − |
|---|---|
| Простой, интерпретируемый | Не ловит долгосрочный тренд |
| Хорошо ловит недельные паттерны | Чувствителен к выбору окна (84 дня) |
| Не требует обучения | |

### Модель 2: Holt Linear (statsmodels)

**Идея.** Экспоненциальное сглаживание с линейным трендом — классика
прогноза временных рядов. Последним наблюдениям присваиваются большие
веса: недавние важнее старых. Поддерживает тренд (рост или падение).

**Математика:**

```python
# Двойное экспоненциальное сглаживание:
level_t = α·y_t + (1-α)·(level_{t-1} + trend_{t-1})
trend_t = β·(level_t - level_{t-1}) + (1-β)·trend_{t-1}
forecast_{t+h} = level_t + h·trend_t
# statsmodels: Holt(daily_net, damped_trend=True).fit(optimized=True)
# Параметры α, β оптимизируются автоматически по AIC
```

| + | − |
|---|---|
| Учитывает тренд | Требует ≥14 точек для стабильной сглаживания |
| Авто-оптимизация параметров | Не учитывает недельную сезонность |
| Damped trend предотвращает взрыв прогноза | |

**На синтетике C001 Holt обычно выигрывает с MAPE ~1%** — это
отличная точность для финансовых прогнозов.

### Модель 3: Linear + Weekday (sklearn)

**Идея.** Гибрид: долгий линейный тренд чистого потока (показывает
рост/падение бизнеса во времени) + поправка на день недели.

**Математика:**

```python
# Шаг 1: сглаживаем дневной поток скользящим средним
smoothed = daily_net.rolling(7, min_periods=1, center=True).mean()
# Шаг 2: линейная регрессия на сглаженном ряду
X = np.arange(len(smoothed)).reshape(-1, 1)
reg = LinearRegression().fit(X, smoothed)
# slope = средний ежедневный рост/падение бизнеса
# Шаг 3: для каждого будущего дня i:
wd = weekday_avg[d.dayofweek]      # из последних 84 дней
trend = intercept + slope · i      # долгий тренд
flow = 0.7·wd + 0.3·trend          # 70% сезон, 30% тренд
```

| + | − |
|---|---|
| Совмещает сезонность и тренд | Может переоценивать тренд на зашумлённых данных |
| Интерпретируемый (slope = рост бизнеса) | Скользящее среднее сглаживает локальные пики |

### Авто-выбор лучшей модели

Все 3 модели проходят hold-out бэктест:

1. Берём всю историю операций
2. Отрезаем последние N=horizon дней (обычно 30)
3. Обучаем модель на данных БЕЗ этих N дней
4. Прогнозируем N дней вперёд
5. Сравниваем прогноз с фактом (который мы скрыли)
6. Считаем метрики MAE / MAPE / RMSE / bias
7. Лучшая по MAE становится базовой моделью прогноза

---

## Метрики качества

| Метрика | Формула | Интерпретация |
|---|---|---|
| **MAE** | (1/n)·Σ|y_pred - y_fact| | Средняя абсолютная ошибка в рублях. Чем меньше — тем точнее. |
| **MAPE** | (100/n)·Σ|y_pred - y_fact|/|y_fact| | Средняя процентная ошибка. Удобно сравнивать модели на разных масштабах. |
| **RMSE** | √((1/n)·Σ(y_pred - y_fact)²) | Корень из средней квадратичной ошибки. Штрафует большие ошибки сильнее. |
| **Bias** | (1/n)·Σ(y_pred - y_fact) | Среднее смещение. + — прогноз завышен, − — занижен. |

### Интерпретация MAPE

| MAPE | Оценка |
|---|---|
| < 5% | Отличная точность |
| 5–15% | Хорошая (типичная для малого бизнеса) |
| 15–30% | Средняя, модель можно улучшить |
| > 30% | Плохая — нужны доп. данные или смена модели |

На синтетике C001 Holt Linear даёт MAPE ~1% — отличная точность.

## Доверительные интервалы

Прогноз без коридора нечестен — мы показываем доверительный интервал
95%, чтобы предприниматель понимал диапазон возможных сценариев.

### Формула

```
CI_95%(t) = forecast(t) ± 1.96 · σ · √t
```

где:
- `forecast(t)` — предсказанный остаток на день t
- `σ` — стандартное отклонение остатков из бэктеста (= MAE)
- `t` — номер дня в горизонте (1, 2, 3, ...)
- `1.96` — z-квантиль для 95% двустороннего интервала

### Почему √t

Ошибки прогноза накапливаются: каждый следующий день несёт
дополнительную неопределённость. Если дневная ошибка σ, то накопленная
за t дней — σ√t (по аналогии с броуновским движением). Это объясняет,
почему коридор **расширяется со временем** — что видно на графике
прогноза.

### Вероятность кассового разрыва

Считается как процент дней, у которых **нижняя граница 95%** ниже нуля.
Это и есть «вероятность того, что денег не хватит» по оценке модели.

- Если нижняя граница > 0 весь горизонт → риск 0%
- Если < 0 в 50% дней → риск 50%

## KPI и риск-баннер

### 5 KPI-карточек

| KPI | Что показывает | Как считается |
|---|---|---|
| Текущий остаток | Сколько денег сейчас на счету | Последний `balance_eod` из выписки |
| Средний приток / день | Сколько в среднем приходит | Σ(положит. signed_amount) / дней в истории |
| Средний отток / день | Сколько в среднем уходит | Σ(отриц. signed_amount) / дней, дельта = чистый burn rate |
| Минимум в прогнозе | Самый низкий прогноз остатка на горизонте | min(forecast), дельта — дата и через сколько дней |
| Runway | Дни до нуля при текущем чистом потоке | Если burn > 0: current_balance / burn. Если приток > оттока: ∞ |

### Риск-баннер

Под KPI-карточками — большой цветной баннер с предупреждением.

| Цвет | Метка | Условие | Что показывает |
|---|---|---|---|
| 🟢 Зелёный | СТАБИЛЬНО | Риск 0%, минимум > 20% от текущего | Минимум прогноза и дату |
| 🟡 Жёлтый | ВНИМАНИЕ | Риск 1–20%, или минимум < 20% от текущего | Запас денег может стать небольшим |
| 🔴 Красный | ВЫСОКИЙ РИСК | Риск > 20%, или прогноз уходит в минус | Дату разрыва, через сколько дней, сумму дефицита, % вероятности |

### Дополнительный KPI — Волатильность

Стандартное отклонение дневного чистого потока. Показывает, насколько
операции «разбросаны» по суммам. Высокая волатильность → широкий
доверительный коридор → менее точный прогноз.

## Стресс-сценарии

Реализация 4-й звёздочки ТЗ. Все 4 типа шоков можно **комбинировать**.

| № | Шок | Слайдер | Как применяется к потокам |
|---|---|---|---|
| 1 | Снижение выручки | 0–60% (шаг 5%) | Только к положительным потокам. `flow = flow·(1 - drop/100)` для `flow > 0` |
| 2 | Задержка поступлений | 0–30 дней (шаг 1) | В первые `delay_days` дни все положительные потоки обнуляются: `flow = min(flow, 0)` |
| 3 | Внеплановый расход | 0–10 000 000 ₽ (шаг 10 000) | Списывается в первый день прогноза: `flows[0] -= expense` |
| 4 | Рост постоянных расходов | 0–100% (шаг 5%) | Увеличивает равномерно ежедневный расход по категориям Аренда/Зарплата/Лизинг/Связь/Комиссии |

### Логика применения (псевдокод)

```python
for each day t in horizon:
    f = base_flow[t]  # предсказание лучшей модели

    # Шок 1: снижение выручки (только к притокам)
    if revenue_drop > 0 and f > 0:
        f = f · (1 - revenue_drop / 100)

    # Шок 2: задержка поступлений
    if delay_days > 0 and t <= delay_days:
        f = min(f, 0)  # обнуляем притоки в первые delay_days

    # Шок 4: рост постоянных расходов
    if fixed_cost_increase > 0:
        f -= daily_fixed_outflow · (fixed_cost_increase / 100)

    # Шок 3: внеплановый расход (только в первый день)
    if extra_expense > 0 and t == 1:
        f -= extra_expense

    flows[t] = f

# Пересчёт кумулятивного остатка
balance = current_balance
for t: balance += flows[t]; forecast[t] = balance
```

## Ограничения

- **Стресс-сценарии — это чувствительность, не вероятностная модель.**
  Мы не строим распределение экономических шоков — пользователь вручную
  задаёт «что если». Вероятность разрыва оценивается по доверительному
  коридору MAE.
- **Прогноз теряет точность после 60 дней** — это видно по расширяющемуся
  коридору. Для горизонта >60 дней нужно дополнять модель экспертными
  оценками и ручными событиями.
- **Регулярные обязательства, которых нет в выписке**, автоматически
  не известны — пользователь должен добавить их во вкладке «События».
- **Нет аутентификации пользователей с разными ролями** — только один
  пароль для всех. Для production нужна схема пользователей (каждый видит
  только свою компанию).
- **Кэш Streamlit хранится в `~/.streamlit/cache`** в открытом виде. Для
  production стоит включить encryption.
